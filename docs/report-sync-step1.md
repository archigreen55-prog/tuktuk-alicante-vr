# Звіт: синхронізація з TukTuk OS, крок 1 — лінії маршруту

Дата: 2026-09-28. План: `docs/plan-tuktuk-os-sync.md` (гілка `claude/tuktuk-os-tour-sync-emwgse`, розд. 8, крок 1).

## Коротко

- Готові `tools/import-tuktuk-os.mjs`, `data/tuktuk-os-map.json` і `data/tour-lines.json`. Прогнано `--dry-run` і справжній запуск.
- **Карта TukTuk OS лінію з OSRM не будує.** Вона показує лінію власника з редактора, а де її немає — пряму пунктиром. OSRM у TukTuk OS рахує лише хвилини, без геометрії. Геометрію з OSRM бере тільки застосунок гіда, і то з публічного сервера.
- **Тому автоматичні лінії поки вимкнені:** для них потрібен сервер маршрутів і мережа. Скрипт уже вміє їх брати, бракує лише адреси сервера. **Потрібне твоє рішення, який варіант обрати** (розд. 3).
- Зараз у TukTuk OS ліній власника 0, автоматичних 0. Тож усі 14 плечей повного туру йдуть нашим A*, і гра поводиться як 0.7.0. Гра `tour-lines.json` ще не читає.

## 2. Як TukTuk OS будує лінію між точками

| Де | Як | Геометрія |
|---|---|---|
| **Карта `/route`**, яку бачать туристи й ти | `buildPathLegs` у `client/src/content/routeLines.ts`: для кожного плеча «звідки→куди» бере лінію з `route-line.json`. Якщо її немає — **пряма пунктиром** між точками | лише лінія власника |
| **Редактор `/route?edit=1`**, вкладка «Лінія» | Ти ставиш вершини торканнями, вони «прилипають» до осі найближчої вулиці на векторній карті (`EditorMap.tsx`, до 30 px). Маршрутизатора там немає | `route-line.json`, `by: "owner"` |
| **Матриця часу** | Власний OSRM 5.27.1 у GitHub Actions (`travel-matrix.yml`), профіль `scripts/osrm/tuktuk.lua` — це автомобільний `car.lua` з обмеженням 30 км/год. Пішохідні вулиці непроїзні. Запит `table/v1` — **лише секунди й метри, без ліній**. Сервер живе, доки йде workflow | немає |
| **Застосунок гіда (Android)** | `OsrmClient.kt`: публічний `router.project-osrm.org`, профіль car, запит `route/v1` з `overview=full`, `polyline6` | є, але лише в телефоні гіда, у файли не пишеться |

Плани TukTuk OS ставлять пріоритет «власник → GPX → **лінія OSRM** → пряма» (ROUTE_EDITOR_PLAN §4.2). Третій рівень ще не зроблено. ROUTE_VISUAL_PLAN §1.2 описує його так: разово попросити OSRM шлях для кожного плеча, не частіше 1 запиту на секунду, зберегти у файл маршруту. Скрипт робить саме це: один запит `route/v1/<профіль>/<звідки>;<куди>` на плече, у порядку туру.

Відомі вади автоматичних ліній, про які пише сам TukTuk OS:
- петлі навколо кварталів через односторонні вулиці, наприклад 3→4 і 4→5;
- проїзд старим містом біля Рамбли, бо в OSM воно відкрите для авто;
- об'їзд пішохідних зон там, де тук-тук має дозвіл.

Саме тут знадобиться твоя ручна лінія, і вона завжди перемагає автоматичну.

## 3. Варіанти для автоматичних ліній — потрібне твоє рішення

Скрипт говорить з будь-яким сервером OSRM. Треба лише вказати адресу в `auto.osrm` у файлі відповідностей або прапорцем `--osrm`. Нічого не встановлював і нікуди не звертався.

| | Варіант | Що потрібно | Збіг з TukTuk OS | Мінуси |
|---|---|---|---|---|
| **А** | **Лінії рахує TukTuk OS.** До наявного workflow `travel-matrix.yml`, де вже працює OSRM з `tuktuk.lua`, додати крок: для кожного плеча турів запитати `route/v1` і зберегти лінії окремим файлом, наприклад `route-line.osrm.json` | Зміна в репозиторії TukTuk OS (їхній агент, з твого дозволу). Нам — нічого: скрипт прочитає файл через `git show`, мені треба лише додати його формат | **повний**: той самий сервер і профіль. Карта TukTuk OS зможе показати ті самі лінії замість прямих — одне джерело правди | Потрібна робота в TukTuk OS |
| **Б** | **Власний OSRM локально**, як у workflow: Docker-образ `osrm-backend:v5.27.1`, витяг OSM Comunidad Valenciana з Geofabrik, `osmium`, `tuktuk.lua` | Встановити Docker і osmium (зараз їх немає), завантажити витяг, кілька хвилин на підготовку. Потім `--osrm http://localhost:5000` | повний | Встановлення на твоєму комп'ютері. Дані OSM — на день завантаження |
| **В** | **Публічний сервер OSRM** `router.project-osrm.org`, як у застосунку гіда | Мережа, ~13 запитів раз на імпорт, без ключів. `--osrm https://router.project-osrm.org` | частковий: профіль car без обмеження 30 км/год, тож на кількох плечах вибір вулиці може відрізнятись | Сервер лише для некомерційного, «розумного» використання, без гарантій. Твоє рішення в TukTuk OS: для редактора його не використовувати |
| Г | Сервіс з ключем (openrouteservice, GraphHopper, Mapbox) | Ключ | інший рушій | Не рекомендую |

**Рекомендую А** як постійне рішення: лінії з'являються там само, де й решта даних туру. **В** — якщо хочеш побачити лінії вже сьогодні, як чернетку до А. Для А й Б результат той самий, що й у TukTuk OS.

## 4. Як працює скрипт

```
node tools/import-tuktuk-os.mjs --dry-run      # лише звіт
node tools/import-tuktuk-os.mjs                # пише data/tour-lines.json
node tools/import-tuktuk-os.mjs --help         # усі прапорці
```

**Джерело для кожного плеча** — перше, що є й пройшло перевірку:
1. лінія власника з `route-line.json` (`by: owner`; схвалена з GPX — `gpx`);
2. автоматична лінія `auto-tuktuk-os` — свіжа з OSRM або з минулого імпорту, якщо кінці плеча не зсунулись;
3. `astar` — лінії немає, гра рахує маршрут сама, як зараз. У файлі — причина (`why`).

**Тури гри** (з `data/tuktuk-os-map.json`):
- `full` — класичний порядок TukTuk OS (1–20), обрізаний до зони: Meliá → 1–10 → 18–20 → Meliá, 14 плечей.
  - Зупинки з карткою: Casa Carbonell, Ayuntamiento, Santa María, Postiguet, Mercado Central.
  - Решта — факти на ходу; Explanada іде одразу після Casa Carbonell.
- `short` — та сама лінія, ті самі 5 зупинок, без фактів на ходу.
- Точки поза зоною випадають автоматично: MARQ, арена, San Fernando, стадіон, ADDA. Замок відсіюється як точка на схилі гори. Colegio San Antonio вимкнено вручну (`exclude`).
- **Postiguet** — точка TukTuk OS на 34 м за межею зони. Вона лишається зупинкою на нашому місці `postiguet`. Лінію до неї скрипт обріже на межі зони, далі гра доїде своїм A*.

**Перевірки ліній** (план, розд. 2.3):

| Перевірка | Що робить скрипт |
|---|---|
| перетинає будівлю чи схил гори | **помилка**: плече бере наступне джерело (авто або A*) |
| виходить за зону посередині | плече бере наступне джерело |
| кінець за межею зони | лінію обрізано на межі, до місця гри — A* |
| точка на будівлі (пам'ятка з Wikidata) | лінія власника починається з першої вершини |
| > 8 м від вулиці OSM | попередження |
| стрибок > 150 м між вершинами (лише ручні лінії) | попередження |
| автоматична лінія > 2 × A* + 200 м | попередження «петля?» |
| OSRM прив'язав точку до дороги далі 40 м | попередження |
| пішохідна вулиця чи площа; проти односторонньої > 20 м | інформація |

**Безпека:**
- лише `git show` трьох файлів: `points.json`, `tours.json`, `route-line.json`;
- мітки `by` / `at` не копіюються;
- перед записом вихід перевіряється на ключі й адреси Supabase.

**Повторний запуск:**
- нічого не змінилось — «без змін», файл не переписується;
- файл правили вручну — запис зупиняється, переписати можна лише з `--force`;
- у звіті видно зсуви точок > 10 м і зміну джерела кожного плеча.

## 7. Що далі

1. **Твоє рішення щодо автоматичних ліній** (розд. 3).
   - А — попросити агента TukTuk OS додати збереження ліній у workflow; я додам читання цього файла.
   - Б або В — вписати адресу в `auto.osrm` і перезапустити імпорт.
2. **Малювати в редакторі TukTuk OS** — там, де автоматична лінія не відповідає реальності. Список плечей — у плані, розд. 2.6. Потім у TukTuk OS «Експорт» → `route:apply` → пуш, у грі — `node tools/import-tuktuk-os.mjs`.
3. **Крок 2** (коли в іншого агента немає незлитих правок у `tour.json`):
   - тексти й точки в `data/tour.json`;
   - зона посадки на точці Meliá;
   - значки й фото в `assets/tour/**` з `CREDITS.md`;
   - `build-city`.
4. **Крок 3** — гра їде по `tour-lines.json`: прогрес уздовж лінії, стрілка, мінікарта, з'їзд → A* до лінії. Після злиття 6b.
