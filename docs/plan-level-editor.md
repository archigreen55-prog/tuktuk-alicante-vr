# План: редактор рівнів Crazy Tuk (тільки план, коду немає)

Дата: 2026-10-08. Статус: **чекає твоєї відповіді; нічого з цього я не кодую, доки ти не погодиш.**
Пов'язано: [plan-arcade-a2.md](plan-arcade-a2.md) (хвиля 2, польоти як тип рівня), [report-arcade-a2-wave1.md](report-arcade-a2-wave1.md).

## 0. Що ти хочеш (як я розумію)

У грі на повноекранній карті сам розставляти ворота рівня: **додавати, перетягувати, видаляти**, задавати **порядок**,
ставити **проміжні точки «через»** (менші, без оцінки; стрілка веде правильним об'їздом), давати **назву рівня й
час**. Рівень зберігається на телефоні, і є простий спосіб **передати його мені**, щоб він став доступним усім
гравцям. На майбутнє закладаємо **типи рівнів**: «не з'їжджай з дороги» (вузькі провулки), «Гори / Каскадер»
(польоти).

## 1. Що вже є і на що спираємось

- Повноекранна карта `src/ui/fullMap.js`: рух, масштаб щипком, місця, пауза гри, тап по мінікарті. Редактор це режим
  цієї карти, не новий екран.
- Ворота зараз беруться з туру `data/tour.json` (місця зі списком `route`) + фініш у точці старту. Проміжні точки вже
  є у форматі `data/arcade-via.json` (версія 0.13.1): `{ тур: { id_воріт: [[x, z], …] } }`.
- Перевірка досяжності й пошук об'їзду вже написані як інструмент `tools/arcade-vias.mjs` (сітка 2 м, A\*,
  правила стін і схилів). Для редактора його ядро виноситься в `src/game/pathfind.js` і запускається в грі.
- Збереження: `localStorage` (як рекорди).

## 2. Формат рівня (JSON, версія 1)

Один файл на рівень; ті самі файли читають і гра, і `sim-arcade`, і редактор.

```json
{
  "schema": 1,
  "id": "short-1",
  "title": { "uk": "Короткий тур", "en": "Short tour", "es": "Tour corto" },
  "type": "standard",
  "start": { "place": "melia" },
  "time": { "par": 309, "mode": "auto" },
  "items": [
    { "k": "gate", "p": [468, 191], "place": "explanada" },
    { "k": "via",  "p": [484, 134], "r": 16 },
    { "k": "gate", "p": [427, 67],  "title": "Ayuntamiento", "fact": "…одна фраза…" },
    { "k": "gate", "p": [582, 191], "finish": true }
  ],
  "rules": {},
  "extras": {}
}
```

- `k: "gate"`: ворота з оцінкою «Точно / Добре / Є». Або з готового місця (`place`: назва, факт беруться з
  `data/tour.json` і `arcade-facts.json`), або вільні (`title` + необов'язковий `fact` до ~70 символів).
- `k: "via"`: проміжна точка: менша, без оцінки, без часу й чайових; зараховується в радіусі `r` (за замовчуванням
  16 м) і перемикає стрілку на наступну; коли до воріт лишається менше 70 м, решта «через» цього відрізка
  пропускається. Порядок у `items` і є порядком проходження.
- `start`: місце (`place`) або точка `{x, z, heading}`.
- `time`: `mode: "auto"` (час від довжини маршруту й моєї симуляції) або `"manual"` + `par` у секундах (ти задаєш сам).
- `type` і `rules`/`extras`: див. розділ 6; нові типи додають поля, не ламаючи старих (завжди є `schema`).
- Три нинішні тури стають такими самими файлами (`data/levels/short.json`, `castle.json`, `full.json`, з уже
  зашитими проміжними точками), тож немає двох різних систем.

## 3. Інтерфейс на телефоні (повноекранна карта в режимі «Редактор»)

Вхід: меню ≡ → **«Редактор рівнів»** (пауза гри, карта на весь екран); на ПК — клавіша `E`. Під час самої гри редактора
нема, тож **на швидкодію забігу він не впливає**.

**Дії (великі кнопки внизу, пальцю зручно):**

| Дія | Як |
|---|---|
| Додати ворота | кнопка «＋ Ворота», потім тап по карті; точка сама прилипає до найближчої дороги в радіусі 20 м і повертається вздовж дороги |
| Додати «через» | кнопка «＋ Через», тап по карті; вставляється в той відрізок, до якого найближча (або в кінець) |
| Перетягнути | натисни точку й, не відриваючи, тягни (палець зміщений вгору, щоб точку було видно); щипок і рух двома пальцями — як і досі, карта |
| Видалити | вибери точку → «🗑»; або перетягни її на смітник у куті |
| Порядок | кнопка «≡ Порядок»: список «1 Ворота…, через, 2 Ворота…», стрілки ↑↓ біля кожного (перетягування за ручку як запасний варіант); на карті номери оновлюються одразу |
| Назва, мова | кнопка «Рівень»: назва (uk / en / es), тип, час (авто / вручну, секунди) |
| Скасувати | ↶ / ↷ (до 30 кроків) |
| Спробувати | «▶ Спробувати» запускає цей рівень з нуля, «≡ → Назад до редактора» повертає |
| Перевірити | «✓ Перевірити»: див. розділ 5 |

Малюнок: ворота — кола з номером (жовті; фініш зелений), «через» — малі білі точки; тонка пунктирна лінія між
сусідніми точками показує **лише в редакторі** порядок (у грі лінії маршруту нема). Червоні попередження над точкою,
якщо з нею проблема.

## 4. Збереження й передача мені

- **На телефоні:** автозбереження чернетки (`localStorage`, `tuktuk.levels.v1`, список рівнів із назвами; «Мої рівні»
  у меню). Нічого не губиться при закритті вкладки.
- **Передати мені:** кнопка **«Поділитися»** робить три речі одним тапом: (1) копіює в буфер **короткий код**
  (JSON, стиснутий у текст ≈ 400–900 символів для 6–12 воріт; координати в метрах), (2) відкриває системне меню
  «Поділитися» (Telegram, пошта…) з цим же текстом, (3) пропонує завантажити файл `.json`. Ти просто вставляєш код сюди,
  в чат цієї сесії (або скидаєш файл у репозиторій у `data/levels-submitted/`).
- **Імпорт:** кнопка «Відкрити код» вставляє код або вибирає файл (для твоїх інших пристроїв і для моїх правок
  назад до тебе).
- **Як рівень стає доступним усім:** я приймаю код → запускаю перевірки (досяжність, мої автопілоти `sim-arcade`,
  розрахунок par, зірок) → кладу як `data/levels/<id>.json` й оновлюю `data/levels/index.json` → підвищую версію, коміт
  у `main`. Гравці бачать рівень у списку після оновлення. (Власних рівнів інших гравців з їх пристроїв на сервері
  не буде: сервера в проєкті немає, і це окреме питання, якщо захочеш «рівні гравців».)

## 5. Перевірки в редакторі («✓ Перевірити»)

Тими самими колізіями й рельєфом, що й гра (шматками по кадру, без підвисання; для маршруту ~700 м орієнтовно 1–2 с на S20):

1. Кожні ворота стоять на вільній землі й досяжні з попередніх (правило стін + схил 33 %; червоне «недосяжні з дороги»).
2. Для кожного відрізка: якщо кращий шлях на 35 % довший за пряму або початково веде вбік більш ніж на 60°, редактор
   **пропонує проміжні точки** (ті самі, які тепер обчислює `tools/arcade-vias.mjs`) одним тапом «Прийняти».
3. Ворота не ближче 25 м одні до одних (інакше їх «пропустить» наступні) і не ближче 12 м до стіни.
4. Оцінка часу: «авто» рахує par з довжини шляху; показує очікувані чайові й зірки.
5. Попередження для типу рівня (розділ 6).

## 6. Типи рівнів (закладаємо поле `type`, поки реалізуємо лише `standard`)

| Тип | Суть | Що додає у файл рівня | Залежності |
|---|---|---|---|
| `standard` | Нинішні правила: ворота, чайові за швидкість, час | нічого | є |
| `stay-on-road` («Не з'їжджай з дороги»), вузькі провулки | Вихід за коридор дороги карається: штраф часу/чайових, червоний край екрана, лічильник «вийшов за дорогу» | `rules: { "corridor": 3.5, "penalty": … }`: допустима відстань від осі дороги графа; редактор малює коридор і не дає ставити ворота поза ним | відстань до графа доріг (є); невелика гілка в `arcade.js`; HUD-індикатор |
| `stunt` («Гори / Каскадер») | Польоти й трампліни: очки за політ (довжина, висота, приземлення), ворота як «майданчики приземлення» | `extras: { "ramps": [{x, z, dir, len, h}], "scoring": {…} }`; інструмент «＋ Трамплін» у редакторі | **вимагає B (польоти) з [plan-arcade-a2.md](plan-arcade-a2.md), розділ B; поки не кодуємо** |

Редактор показує лише ті інструменти, які потрібні типу рівня; невідомі поля нових типів старі версії просто ігнорують.

## 7. Етапи, час, ризики

| Етап | Що | Час | Ризик | Навантаження на телефон |
|---|---|---|---|---|
| E0 | Рівні як JSON (`data/levels/*.json`) замість ворот із `tour.json`; `Arcade` приймає рівень; три нинішні тури конвертуються (з проміжними точками); `sim-arcade`, par, рекорди за `id` рівня | 1–1.5 дні | середній: чіпає основу аркади (перевіряємо `sim-arcade`, тести) | нуль |
| E1 | Ядро редактора: додати / перетягнути / видалити / порядок, назва, час, автозбереження, ↶/↷ | 3 дні | середній: дотики на карті (щипок проти перетягування) | нуль у грі; карта в паузі |
| E2 | «через», перевірки (`pathfind.js` у грі), підказка об'їзду, «Спробувати» | 2 дні | середній: швидкодія пошуку шляху на телефоні | пошук до 1–2 с у паузі, шматками |
| E3 | Поділитися / імпорт, список «Мої рівні» й вбудованих рівнів у меню | 1 день | низький | нуль |
| E4a | Тип `stay-on-road` (правило, HUD) | 2 дні | низький–середній | мале |
| E4b | Тип `stunt` | після B (польоти) | залежить від B | залежить від B |

Разом E0–E3 ≈ **7–8 днів**. Якщо потрібен лише швидкий результат: E0 + файл `data/levels/*.json` редагується мною за твоїми
кодами координат, а редактор додається згодом.

## 8. Що я зробив уже зараз (до редактора)

У версії 0.13.1 з'явився `data/arcade-via.json` і механіка «через» у `Arcade` (стрілка веде через проміжні точки, мінікарта
показує їх малими білими точками); `tools/arcade-vias.mjs` обчислює їх для всіх стандартних турів. Формат уже сумісний із
розділом 2 (`items[].k = "via"`), конвертація в E0 механічна.

## 9. Питання до тебе (відповідай коротко, коли захочеш рухатись)

1. Редагувати будеш лише ти, чи редактор має бути в грі для всіх гравців? (Для всіх: простіший режим, захист від
   «поганих» рівнів, окремий розділ «рівні гравців» без сервера не вийде.)
2. Скільки воріт максимум на рівні? Рекомендую 3–12.
3. Час: автоматичний (я рахую par) чи ти хочеш мати право вказати вручну? (У плані є обидва.)
4. Назви рівнів: усіма трьома мовами (uk / en / es) чи спершу лише українською?
5. Починати з E0 (рівні як файли), чи спершу тільки E1 (редактор поверх старих турів)? Моя порада: E0 → E1 → E2 → E3.
