## 1. Як виміряти запас продуктивності (крок 5.0)

### Що таке `?stress`
Параметр `?stress=N` малює всю сцену N разів за кадр. Зображення те саме, але GPU робить у N разів більше роботи. Якщо на `stress=3` досі 90 FPS, то зараз гра використовує менше третини можливостей GPU, і запас щонайменше 3×.

### Адреси для шолома
Відкривати по черзі. У кожній натиснути ENTER VR, почекати ~10 с і подивитись на панель приладів. FPS увімкнеться сам.

| N | Адреса |
|---|---|
| 1 | https://archigreen55-prog.github.io/tuktuk-alicante-vr/?v=0.5.0&fps&stress=1 |
| 2 | https://archigreen55-prog.github.io/tuktuk-alicante-vr/?v=0.5.0&fps&stress=2 |
| 3 | https://archigreen55-prog.github.io/tuktuk-alicante-vr/?v=0.5.0&fps&stress=3 |
| 4 | https://archigreen55-prog.github.io/tuktuk-alicante-vr/?v=0.5.0&fps&stress=4 |
| 6 | https://archigreen55-prog.github.io/tuktuk-alicante-vr/?v=0.5.0&fps&stress=6 |

**Простіше без перезавантажень:** відкрий першу адресу, увійди у VR і **утримуй X 1 с**. Рівень перемикається по колу ×1 → ×2 → ×3 → ×4 → ×6 → ×8 → ×1, на панелі видно «навантаження ×N».

### Що дивитися на панелі (у кожній з трьох точок)
Точки:
1. На старті, погляд уперед по вулиці.
2. Поворот голови в бік довгої вулиці або моря — у кадрі найбільше міста.
3. На Rambla: проїхати ~200 м прямо від старту.

Що записати:

| Рядок на панелі | Що означає |
|---|---|
| **`90 FPS`** (великий) | Кадри на секунду. Зелений — тримає частоту, жовтий — просідає, червоний — сильно просідає |
| **`GPU x.x мс`** | Скільки GPU витрачає на кадр. `н/д` — браузер не дає цей замір (розширення `EXT_disjoint_timer_query_webgl2`), тоді орієнтуємось лише на FPS. При 90 Гц бюджет — 11.1 мс |
| **`CPU x.x мс`** | Скільки JavaScript витрачає на кадр. Якщо він сам по собі близький до 11 мс, упираємось не в GPU, а в процесор |
| **`90 Гц · 24 calls · 87k tris`** | Частота екрана шолома, draw calls і трикутники (за один прохід, для обох очей разом) |

**Що мені надіслати:** таблицю «N → FPS (і GPU мс, якщо є) у трьох точках». Найбільше N, за якого тримається 90 FPS, — це наш запас для текстур.

### Автоматичний перехід на 72 Гц
При `stress=1` (звичайна гра) гра сама перемикає шолом на 72 Гц, якщо 3 секунди поспіль FPS нижчий за 86. Спрацьовує один раз за сесію, на панелі з'являється «Частота 72 Гц (було N FPS)». При `stress>1` автоперехід вимкнено, щоб не заважати заміру. Примусово: `&hz=72` або `&hz=90`. Якщо в звичайній грі побачиш цей напис — скажи.

## 2. Кермо як деталь (крок 5.1) + V-подібна форма

**Форма.** Як на мопеді чи Bajaj RE / Piaggio Ape. Від затиску на рульовій колонці дві половини керма йдуть убік і трохи вгору, загинаються назад до водія, на кінцях гумові ручки. Праворуч — металевий наконечник і світла риска на ручці, щоб було видно прокрутку газу. Перед обома ручками — гальмівні важелі.

**Геометрія** (метри; від точки очей водія):

| | Значення |
|---|---|
| Центри ручок | 0.44 м попереду, 0.33 м нижче очей, 0.60 м одна від одної |
| Напрям ручки | Відхилена назад на 40° від поперечної осі, вгору на ~4.5° |
| Довжина ручки | 13 см, діаметр 5.6 см |
| Рульова вісь | Через затиск, нахилена на 25° назад до водія |
| Упор керма | ±35° |

Кермо повертається й у режимі стіка, і з клавіатури (A/D). Кут — пропорційний повороту: повний стік чи клавіша дають ±35°. Права ручка показує газ і від тригера, і від W.

**Педаль гальма.** Стоїть у підлозі під правою ногою водія. При гальмуванні (лівий тригер або S) натискається пропорційно силі гальма, повністю — на 24°, так що накладка лягає пласко. Педаль — частина меша корпусу, повертається у вершинному шейдері, тому **draw calls не додає**. Керування це не змінює.

**Draw calls:** 22 → 24 (кермо й права ручка). Ще +2, поки видно рукавички. Трикутники: 87k, майже без змін.

## 3. Руки на кермі (крок 5.2)

### Схема кнопок

| Дія | Режим «руки на кермі» | Режим стіка |
|---|---|---|
| Тримати кермо | **Обидва grip затиснуті** | — |
| Поворот | **Руками, як кермо мопеда:** праву руку до себе, ліву від себе — праворуч. Коли кермо відпущене — лівий стік | Лівий стік |
| Газ | **Прокрутити праву руку на себе** (як ручку газу) або правий тригер | Правий тригер |
| Гальмо / задній хід | Лівий тригер; утримати на місці 0.4 с — задній хід | Так само |
| Ручник | A | A |
| Гудок | B | B |
| **Перемкнути режим** | **Натиск правого стіка** | Натиск правого стіка |
| Лічильник FPS | X (коротко) | X (коротко) |
| Тест навантаження | Утримати X 1 с | Утримати X 1 с |
| Сила віньєтки | Натиск лівого стіка | Натиск лівого стіка |
| Перецентрування | Y (утримати 1 с) | Y (утримати 1 с) |
| Повернутися на дорогу | **A + B разом 1 с** (гудок при цьому мовчить) | A + B 1 с або обидва grip 1 с |

- Режим вибирається на стартовому екрані («Керування у VR») або натиском правого стіка в грі. Вибір зберігається.
- **Змінилось для стік-режиму:** натиск правого стіка більше не ручник (ручник лише на A). X спрацьовує при відпусканні: довше 1 с — це вже тест навантаження.

### Як працює
- **Хват:** обидва grip затиснуті — на ручках з'являються рукавички, бруски контролерів ховаються. Короткий «клік» вібрацією в кожній руці.
- **Поворот:** кут керма = кут лінії «ліва рука → права рука» навколо рульової осі. Згладження 50 мс, мертва зона 2°, упор 35°.
  - Руки **не треба тягнути до ручок**: можна тримати на колінах, важить лише кут між руками.
  - Повне кермо — ~±13 см руху кожної руки вперед-назад.
  - Висота рук і відстань між ними на поворот не впливають.
- **Газ прокруткою:** нейтраль — поза правої руки в момент хвату. Мертва зона 3°, повний газ при 25° на себе. Від себе — нічого.
  - Поворот керма з нерухомими зап'ястями не дає газу. Через те що ручка загнута назад і вгору, частина повороту керма виглядала б як прокрутка (у першій версії це давало хибні 12% газу). Тепер ця частина віднімається.
- **Відпустив grip на ходу:**
  - газ одразу 0 («пружина»);
  - кермо плавно вирівнюється, швидше на більшій швидкості, до 40°/с; на місці не вирівнюється;
  - тук-тук котиться накатом, **без автоматичного гальма**;
  - через 1.5 с на панелі: «Візьмись за кермо (grip)»;
  - лівий стік у цей час працює як запасне кермо.
- **Знову схопив:** кермо за 0.2 с плавно доходить до положення рук, без ривка.
- **Руки схрещені або ближче 15 см:** хват не зараховується, на панелі: «Тримай руки по боках».
- **Втрата трекінгу** контролера (наприклад, руки дуже низько): рука вважається відпущеною — газ 0, кермо вирівнюється. Трекінг повернувся — хват продовжується без ривка.
- **Вібрація двигуна:** слабка, в правому контролері, поки права рука тримає ручку. Трохи сильніша на газу. Вимикається на стартовому екрані й зберігається.

## 4. Як перевіряли

Усе — в емуляторі Quest 3 (IWER від Meta) у headless Chrome. Позиції й повороти контролерів задавались скриптом.

| Перевірка | Очікувано | Результат |
|---|---|---|
| Хват обома grip, руки рівно | тримає, кут 0 | тримає, 0°, рукавички видно, контролери сховані |
| Права рука на 10 см назад, ліва на 10 см вперед | ~−16.8°, праворуч | −16.6°, steer +0.44 |
| Навпаки | ліворуч | +16.6°, steer −0.44 |
| Поворот керма без прокрутки | газ 0 | газ 0 (у першій версії був 0.12 — виправлено) |
| Прокрутка правої руки на 20° | газ ≈ 0.77 | 0.77, ручка в кабіні повернулась на 20°, тук-тук поїхав |
| Відпустити на 20 км/год у повороті | газ 0, кермо до 0, котиться | 16.6° → 0° (на 20 км/год — за ~0.8 с), газ 0, швидкість плавно спадає |
| Знову схопити з повернутими руками | без ривка | −8° через мить, −16.6° згодом |
| Схрещені руки | не хват + напис | так |
| Обидва grip 6 с у режимі рук | не скидає | позиція не змінилась |
| A + B 1 с | на дорогу | так |
| X коротко / X 1 с | FPS / навантаження | так |
| Натиск правого стіка | режим змінюється, зберігається | так |
| Стік-режим (регресія етапу 4) | як раніше | так, крім двох навмисних змін вище |
| Клавіатура | як раніше | так; A/D повертають кермо, S натискає педаль |
| Живий сайт 0.5.0 | вхід у VR, хват | так |

## 5. Що не вдалося або не перевірено
1. **Нічого не перевірено на справжньому Quest 3:** відчуття керма руками, знак прокрутки, вібрація, реальний FPS. Перевірити може лише шолом.
2. **Знак прокрутки газу** вибрано як на мотоциклі: верх ручки до себе = газ. Якщо на справжньому контролері вийде навпаки — це одна константа, виправлю одразу.
3. **Правило втрати трекінгу.** Емулятор завжди позначає позицію контролера як «оцінену». Тому «оцінена» позиція вважається втратою трекінгу лише тоді, коли ця рука вже мала справжній трекінг у цій сесії. На Quest має працювати як задумано, але саме цей випадок в емуляторі не перевірити.
4. **Час GPU** може показати «н/д», якщо браузер Quest не дає цього розширення. Тоді запас оцінюємо лише за FPS на різних `stress`.
5. **Рукавички й кермо — прості low-poly** з брусків. Косметику можна підправити з текстурами.
6. **Не робив** опцію «grip як перемикач» (натиснув — схопив). У плані вона стоїть як резервна, якщо втомлюватимуться пальці.
7. Текстури (5.3–5.7) не починав, як домовились.

## 6. Що перевірити в шоломі
1. Замір запасу — розділ 1, три точки, N = 1…6.
2. Режим «руки на кермі»:
   - хват і поворот;
   - чи зручно тримати руки там, де хочеш;
   - прокрутка на себе дає газ (не навпаки?);
   - чи не з'являється газ під час повороту;
   - поведінка, коли відпускаєш кермо на ходу.
3. Чи досить слабка вібрація двигуна.
4. Форма керма й розташування ручок: чи ручки «там, де руки»; педаль видно, якщо глянути вниз.
