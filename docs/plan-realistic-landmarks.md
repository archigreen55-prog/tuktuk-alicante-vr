Ще одна обставина: Sketchfab 2026-08-12 продано KitBash, а магазин моделей ще у 2024 переїхав на Fab. Якщо щось знайдемо, варто одразу завантажити модель і зберегти сторінку ліцензії.

### 2.3 Як знімати будівлю (Mercado як приклад)
1. **Світло:** хмарний день або рано вранці, поки фасад у тіні. Різке сонце запікає тіні в текстуру. Для скану найкраще **неділя зранку**: менше людей, машин і відчинених кіосків.
2. **Фото, не відео.** Без зуму, без спалаху. Фокус і експозицію зафіксувати (довгий тап на екрані). 150–300 кадрів на будівлю.
3. **Перекриття:** кожен наступний кадр перекриває попередній на **70–80 %**, крок кута не більше **~30°**. Кожна точка фасаду — щонайменше на 3 кадрах.
4. **Проходи вздовж фасаду:**
   - на 2–3 відстанях: протилежний тротуар, середина, біля стіни;
   - на 3 висотах: присівши, на рівні очей, з піднятими руками (або з лавки).
   - Високі частини (вежі, купол) — з нахилом камери вгору 10–35°.
5. **Кути й ротонда:** обходь по дузі, не перескакуючи. Закінчи там, де почав (замкнене коло).
6. **Спочатку загальні кадри** всієї будівлі, потім деталі (портал, вежі).
7. **Що не вийде з вулиці:** дах і верх купола. Там будуть діри. Для гри це нормально: гравець на вулиці. Дах лишимо простим або змоделюємо окремо.

### 2.4 Експорт і зменшення під Quest
**Бюджет на одну пам'ятку** (моя пропозиція з запасом під браузер): **50–100 тис. трикутників, 1–2 draw calls, одна текстура 2048² у KTX2**.
- Meta для рідних застосунків на Quest 3 дає 1.3–1.8 млн трикутників і 200–1000 draw calls на кадр. Для WebXR чисел не дає, але радить KTX2/Basis.
- Наш кадр зараз ~160 тис. трикутників і ~17 draw calls на око, запас GPU 6–8×. 2–3 скани в кадрі влазять.
- Пам'ять текстури 2048² з mip:
  - без стиснення ≈ 21 МБ;
  - KTX2 → ASTC ≈ 5 МБ (UASTC);
  - ETC1S ≈ 3 МБ.

  Той самий KTX2 варто застосувати й до атласу фото-фасадів, коли пам'яток стане 5+ (зараз атлас ≈ 24 МБ).

**Кроки:**
1. **Експорт GLB** з програми (найвища якість, яку дає безкоштовний план).
2. **Blender** (працює на HD 4600):
   - обрізати землю, сусідні будинки, машини;
   - закрити діри;
   - Decimate: Collapse з Ratio або Planar для пласких фасадів.
   - Для найкращого вигляду: зробити спрощену модель, **запекти нормал-карту** з детальної (Cycles → Bake → Normal, «Selected to Active»). Рельєф карнизів тоді видно при 20–50 тис. трикутників.
3. **gltf-transform** (`npm i -g @gltf-transform/cli`, версія 4.5; для KTX2 потрібна утиліта `ktx` з KTX-Software ≥ 4.4, є .deb для Ubuntu/Mint):
   ```
   gltf-transform inspect scan.glb
   gltf-transform optimize scan.glb mercado.glb --compress meshopt --texture-compress ktx2 \
       --texture-size 2048 --simplify-ratio 0.1 --simplify-error 0.001
   ```
   Або по кроках: `weld` → `simplify --ratio 0.1 --error 0.001` → `resize --width 2048 --height 2048` → `uastc --level 2 --zstd 18` (або `etc1s --quality 128`) → `meshopt --level high`. Альтернатива — `gltfpack -i scan.glb -o mercado.glb -si 0.1 -cc -tc -tl 2048` (рідний архів з GitHub meshoptimizer; версія з npm текстури не стискає).
4. **Завантаження в гру:** GLTFLoader + MeshoptDecoder + KTX2Loader (транскодер з того самого CDN three@0.186.1). Файл 2–5 МБ на пам'ятку (оцінка). Вантажити після старту, у фоні, як і фото.

### 2.5 Як поставити модель точно на місце будинку з OSM
- **Координати.** glTF — метри, вісь Y вгору. У грі x — схід, z — південь, одиниці теж метри. Потрібні лише масштаб, поворот навколо вертикалі й зсув.
- **Інструмент (план, ~0.5 дня): `tools/place-model.mjs`.** Скаже, які 2–3 кути будинку взяти:
  1. `prepare-facade.mjs --list` показує номери кутів контуру OSM.
  2. Ти (або я) в Blender знаходиш ті самі кути на моделі — координати видно в панелі N.
  3. Скрипт рахує масштаб, поворот і зсув методом найменших квадратів (перетворення подібності 2D) і пише в `data/facades.json` поле `"model": { "src", "position", "rotation", "scale" }`.
  4. Висоту (y) бере з рівня землі моделі.
- **У грі:** процедурні стіни будинку ховаються так само, як під фото-фасадом. Зіткнення лишаються з контуру OSM — фізика не змінюється.
- **GPS телефона помиляється на кілька метрів** — лише як грубе розміщення. ODM уміє GPS і контрольні точки (`--gcp`), Polycam — лише в платному Business.
- **Не можна** брати моделі з Google Photorealistic 3D Tiles (наприклад, через Blosm) — умови Google це прямо забороняють.

**Для архітектури погано.**
- Моделі «об'єктні»: невидимі боки вигадують.
- Метричного масштабу немає: ринок 42 м вийде «іграшкою», яку треба розтягувати на око.
- Вікна й деталі розпливаються, текстури низької роздільності.
- Дослідження ICCV 2025 (ArchiSet) пише про «втрату об'ємних деталей, неповні вікна».

**Годиться для дрібних предметів біля маршруту:** скульптура, кіоск, лавка, фонтан — там, де точність не важлива, а 3D-форма краща за пласку картинку.

| Пам'ять GPU | 5–10 МБ на пам'ятку без стиснення, ≈ 2 МБ з KTX2 | ×2 (ще карта) | ≈ 5 МБ (одна 2048² KTX2) | ≈ 5 МБ |
| Вплив на FPS | ≤ 3–4 % GPU, коли пам'ятка на пів екрана | трохи більше | помірний: вершини + одна вибірка текстури; перевіряти в шоломі | так само |
| Завантаження | 0.1–0.4 МБ | +0.2 МБ | 2–5 МБ | 1–5 МБ |
| Ліцензії | свої фото — жодних питань; Commons — лише CC BY / BY-SA / CC0 | так само | свій скан — твій (RealityScan / KIRI) | TRELLIS MIT — ок; Hunyuan — ні (ЄС) |

Цифри роботи й FPS для скану й ШІ — **оцінки**, їх перевіримо на першому пілоті.

## 6. Питання до тебе
1. **Який у тебе телефон** (iPhone чи Android, модель)? RealityScan і KIRI працюють на обох, але якість камери й наявність LiDAR (iPhone Pro) впливають на результат.
2. **Чи буде гра рекламувати твої тури** (посилання, назва компанії)? Від цього залежить, чи підходять ліцензії NC і умови Polycam/Scaniverse.
3. **Робимо L1** (тест з готовим сканом Santa María) перед тим, як ти підеш знімати ринок?
4. Чи можеш зняти ринок **рано в неділю** (мало людей, кіоски закриті)? Для фото-фасаду й для скану це однаково важливо.
